# 會議瀏覽器為何如此運作

當 Vibe 自行承載頁面時，通話會更容易錄製：應用程式控制視窗、知道何時正在錄音，並可顯示只有一個操作的工具列。這項設計取決於作業系統實際允許什麼。

## 為何使用 URL scheme 而非 https 點擊

瀏覽器絕不會將 `https://` 連結交給已安裝的應用程式，除非該應用程式是預設瀏覽器。會議應用程式的運作方式相反：它們註冊自己的 scheme，並由其頁面或安裝程式呼叫。

Vibe 的做法相同：

- `vibe://open/?url=https://…` 會在 Vibe 的瀏覽器視窗中開啟目標。任何應用程式、指令稿或捷徑都可以呼叫它。Vibe 會在 Rust 中驗證 URL，並拒絕任何不是 https 且格式不正確的內容。
- **設定 → 錄音 → 在 Vibe 中開啟**會將連結貼到相同路徑。

在 Chrome、Edge 或 Firefox 中點擊 `https` 連結仍然會開啟該瀏覽器。刻意不將 Vibe 設為預設瀏覽器：這樣會為了服務單一功能而接管電腦上的每個連結。

## 為何內容檢視是隔離的

內容視窗是擁有自己資料目錄的普通 webview。服務的 Cookie 絕不會與應用程式的儲存空間混合，頁面中不會注入任何指令稿，而相機和麥克風提示來自頁面本身，而非由 Vibe 代使用者授予。內嵌頁面會被視為不受信任的網頁內容，而非應用程式的一部分。

工具列提供網址、上一頁、下一頁、重新載入、關閉，以及**在系統瀏覽器中開啟**。最後一項操作是供拒絕在內嵌 webview 中執行之服務使用的逃生出口。

## 為何錄音保持手動

會議清單中的主機會將視窗變成會議工作階段：工具列會顯示**錄製此會議**。錄音仍然是手動的——在通話前或通話期間按下按鈕，從工具列或主視窗停止。自動開始會錄下使用者沒有要求錄製的通話，並會在沒有明確操作的情況下令麥克風指示燈出現。

錄音期間關閉視窗時，會詢問要停止還是繼續在背景錄音，因此離開通話不會在無聲無息中捨棄或繼續錄音。

## 限制

- 只有 `vibe://open/` 連結會自動開啟。`https` 點擊需要 Vibe 不會作出的預設瀏覽器決定。
- 大量使用 DRM 或對 WebRTC 不友善的網站，在系統瀏覽器中可能運作得更好；**在系統瀏覽器中開啟**是支援的退回方式。
- Windows 是首先驗證的平台。其他平台使用各自的 webview，若視窗無法承載通話，則退回系統瀏覽器。
- 註冊 Zoom、Teams 和 Webex scheme 是選擇性的，適用於 Windows 和 Linux，不適用於 macOS。
