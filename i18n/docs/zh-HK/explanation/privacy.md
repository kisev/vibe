# 私隱與離線設計

Vibe 的構建方式令一般轉錄路徑毋須帳戶，也毋須雲端服務。應用程式會啟動本機伺服器，伺服器從磁碟載入模型，音頻會在同一部電腦上解碼和轉錄。

## 什麼會留在本機

- 音頻檔案、錄音、匯出檔案和轉錄文字。
- 模型和 ffmpeg 二進位檔。
- 專案資料夾中的專案歷史。
- 桌面應用程式與 `vibe-server` 之間的本機 HTTP API，繫結於回送位址。

應用程式不會傳送任何遙測資料。**報告問題**會從本機診斷資訊建立預填問題並開啟 GitHub；在你檢閱並送出之前，不會提交任何內容。

## 何處會使用網絡

| 功能 | 網絡連線 |
| --- | --- |
| 模型下載 | 提供模型檔案的主機 |
| 從連結轉錄 | 媒體主機，以及 GitHub 上的 yt-dlp 二進位檔 |
| 更新檢查 | 網站上的頻道檔案 |
| 使用 Claude 或 OpenAI 的 AI 摘要 | 已設定的供應商 |
| 使用 Ollama 的 AI 摘要 | Ollama URL，預設為本機 |
| 手機接力 | 手機與這部電腦之間全程端對端加密的中繼伺服器 |

轉錄引擎本身沒有任何網絡路徑。

## 手機接力

手機和桌面電腦會透過 iroh 連線。中繼伺服器轉送端對端加密的流量，因此中繼只能轉發它無法讀取的位元組；轉錄仍會在這部電腦上進行，而 Vibe 必須保持開啟，手機接力才能運作。

## 取捨

- 本機模型會佔用磁碟空間，並使用電腦的 CPU 或 GPU。[引擎與 GPU 選擇](/vibe/docs#engine)說明了當中的分工。
- 雲端摘要會將轉錄文字傳送給你選擇的供應商。將平台保留為 Ollama 便可讓文字留在本機。
- 更新會從網站上的靜態檔案檢查，這會揭示應用程式曾檢查某個頻道，但不會揭示它轉錄了什麼。
