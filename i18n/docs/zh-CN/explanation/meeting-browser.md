# 会议浏览器为何这样工作

当 Vibe 自己承载页面时，通话更容易录制：应用控制窗口，知道录音何时进行，并能显示一个只有单一操作的栏。该设计受操作系统实际允许范围的约束。

## 为什么用 URL 方案而不是 https 点击

浏览器绝不会把 `https://` 链接交给已安装的应用，除非该应用是默认浏览器。会议应用的做法相反：它们注册自己的方案，并由其页面或安装程序调用。

Vibe 也是如此：

- `vibe://open/?url=https://…` 会在 Vibe 的浏览器窗口中打开目标。任何应用、脚本或快捷方式都可以调用它。Vibe 在 Rust 中验证 URL，并拒绝任何不是 https 或格式不正确的内容。
- **设置 → 录音 → 在 Vibe 中打开**会把链接粘贴到同一条路径。

在 Chrome、Edge 或 Firefox 中点击 `https` 链接仍会打开该浏览器。让 Vibe 成为默认浏览器是有意排除在范围之外的：为了一个功能，它会接管机器上的每个链接。

## 为什么内容视图是隔离的

内容窗口是一个带有自己数据目录的普通 webview。服务 Cookie 绝不会与应用存储混合，不会向页面注入任何脚本，摄像头和麦克风提示来自页面本身，而不是由 Vibe 代表用户授予。嵌入式页面被视为不受信任的 Web 内容，而不是应用的一部分。

该栏提供地址、后退、前进、重新加载、关闭和**在系统浏览器中打开**。最后一个操作是服务拒绝在嵌入式 webview 中运行时的逃生通道。

## 为什么录音保持手动

会议列表中的主机会把窗口变为会议会话：该栏会显示**录制此会议**。录音仍是手动的——在通话前或通话中按下按钮，从栏或主窗口停止。自动开始会录制用户没有要求录制的通话，并会让麦克风指示器在没有明确操作的情况下出现。

录音时关闭窗口会询问是停止还是在后台继续录音，因此离开通话不会悄悄丢弃或继续录音。

## 限制

- 只有 `vibe://open/` 链接会自动打开。点击 `https` 需要 Vibe 不做的默认浏览器决定。
- DRM 较重或对 WebRTC 不友好的网站可能在系统浏览器中工作得更好；**在系统浏览器中打开**是受支持的回退方式。
- Windows 首先得到验证。其他平台使用自己的 webview，如果窗口无法承载通话，则回退到系统浏览器。
- 注册 Zoom、Teams 和 Webex 方案是可选的，在 Windows 和 Linux 上可用，macOS 不可用。
