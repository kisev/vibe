# 隐私与离线设计

Vibe 的设计使常规转录路径无需账户，也无需云服务。应用会启动本地服务器，服务器从磁盘加载模型，音频在同一台机器上解码和转录。

## 哪些内容留在本地

- 音频文件、录音、导出内容和转录文本。
- 模型和 ffmpeg 二进制文件。
- 项目文件夹中的项目历史。
- 桌面应用与 `vibe-server` 之间的本地 HTTP API，绑定到回环地址。

应用不发送任何遥测。**报告问题**会根据本地诊断构建一个预填的问题并打开 GitHub；在你审阅并发送之前，不会提交任何内容。

## 在哪里使用网络

| 功能 | 网络访问 |
| --- | --- |
| 模型下载 | 提供模型文件的主机 |
| 从链接转录 | 媒体主机，以及 GitHub 上的 yt-dlp 二进制文件 |
| 更新检查 | 网站上的通道文件 |
| 使用 Claude 或 OpenAI 的 AI 摘要 | 配置的提供方 |
| 使用 Ollama 的 AI 摘要 | Ollama URL，默认为本地 |
| 手机接力 | 手机与这台电脑之间的端到端加密中继 |

转录引擎本身没有网络路径。

## 手机接力

手机和桌面通过 iroh 连接。中继承载端到端加密流量，因此中继转发的是它无法读取的字节；转录仍在这台电脑上进行，且 Vibe 必须保持打开，接力才能工作。

## 权衡

- 本地模型会占用磁盘空间，并使用机器的 CPU 或 GPU。[引擎与 GPU 选择](/vibe/docs#engine)解释了这种分工。
- 云端摘要会把转录文本发送到你选择的提供方。将平台保持为 Ollama 可让它留在本地。
- 更新检查通过网站上的静态文件进行，这只会暴露应用检查过某个通道，而不会暴露它转录了什么。
