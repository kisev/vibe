# Приватность и работа офлайн

Vibe устроен так, что обычная транскрипция не требует учётной записи и облачного сервиса. Приложение запускает локальный сервер, сервер загружает модель с диска, а звук декодируется и транскрибируется на той же машине.

## Что остаётся локально

- Аудиофайлы, записи, экспорт и расшифровки.
- Модели и бинарные файлы ffmpeg.
- История проектов в папке проектов.
- Локальный HTTP API между настольным приложением и `vibe-server`, привязанный к loopback.

Приложение не отправляет телеметрию. **Сообщить о проблеме** собирает предзаполненный отчёт из локальной диагностики и открывает GitHub; ничего не отправляется, пока вы не проверите и не отправите его.

## Где используется сеть

| Функция | Сетевые обращения |
| --- | --- |
| Загрузка модели | Хост, отдающий файл модели |
| Транскрипция по ссылке | Медиахост и GitHub для бинарного файла yt-dlp |
| Проверка обновлений | Файл канала на сайте |
| Сводка ИИ через Claude или OpenAI | Настроенный провайдер |
| Сводка ИИ через Ollama | URL Ollama, по умолчанию локальный |
| Передача с телефона | Ретранслятор со сквозным шифрованием между телефоном и этим компьютером |

У самого движка транскрипции нет сетевого доступа.

## Передача с телефона

Телефон и настольное приложение соединяются через iroh. Ретранслятор передаёт трафик со сквозным шифрованием, поэтому он пересылает байты, которые не может прочитать; транскрипция по-прежнему выполняется на этом компьютере, и для работы передачи Vibe должен оставаться открытым.

## Компромиссы

- Локальные модели занимают место на диске и используют CPU или GPU машины. Разделение объясняет раздел [Движок и выбор GPU](/vibe/docs#engine).
- Облачная сводка отправляет текст расшифровки выбранному провайдеру. Оставьте платформу на Ollama, чтобы сохранить его локально.
- Обновления проверяются по статическим файлам на сайте, что раскрывает факт проверки канала приложением, но не то, что оно транскрибировало.
