# Почему каналы обновлений устроены именно так

У GitHub есть только «последний выпуск». Vibe нужны три ветки — Релиз, Beta и Dev, — между которыми пользователь может переключаться, в том числе из более старой установки. Это несоответствие и определяет устройство каналов.

## Почему сайт, а не GitHub

Приложение читает `updater/<channel>.json` с сайта. Каждый файл — это `latest.json`, созданный релизной сборкой и скопированный рядом с остальными:

- Релиз → `stable.json`
- Beta → `beta.json`
- Dev → `dev.json`

Файл канала — статический ресурс, развёрнутый вместе с сайтом, поэтому указание ветки на сборку — это коммит, а не правка выпуска. Это также позволяет отсутствующему каналу означать нечто точное: `404` или `410` — «на этой ветке ничего нет», и приложение сообщает об отсутствии обновлений. Если бы при отсутствии файла приложение переключалось на другой канал, пользователь Beta без кандидата молча перешёл бы на Релиз.

## Почему у beta суффикс `-rc.<n>`

Semver упорядочивает так:

```text
X.Y.Z-dev.N < X.Y.Z-rc.N < X.Y.Z
```

Этот порядок и есть вся причина такого написания. При строгом сравнении обновления переход Dev → Beta → Релиз всегда идёт вперёд; особое переопределение не нужно.

В более ранней ветке использовался `-beta.N`, но в ней не было dev-канала. `X.Y.Z-beta.N` выше `X.Y.Z-dev.N`, поэтому beta-сборка выглядела бы новее любой dev-сборки и ломала переключение. Канал beta сохраняет своё имя; суффикс версии — только `-rc.<n>`.

## Почему beta содержит только кандидатов

В `beta.json` записывается только версия `X.Y.Z-rc.<n>`; обычный релиз отклоняется. Это сохраняет смысл ветки beta: это ветка кандидатов, а не вторая стабильная ветка. После стабильного выпуска установка Beta переходит на финальный, переключая канал на Релиз, где `X.Y.Z` выше своих кандидатов.

## Обновления только вперёд

Обновление идёт только вперёд. Плохой выпуск исправляется выпуском более нового, для чего и нужна ветка beta: поймать его до того, как он попадёт в Релиз. Поэтому установка Релиза или Beta, выбравшая Dev, видит «Обновлений нет»: каждая dev-сборка ниже уже установленной версии. Чтобы перейти на ветку dev, нужно один раз вручную установить dev-сборку; после этого канал Dev обновляет её дальше.

## Компромиссы

- **Скопированные манифесты** означают, что смена канала — это коммит в `main` плюс развёртывание сайта, а не вызов API. Задержка — минуты, а история доступна для проверки.
- **Отсутствие переключения между каналами** означает, что пользователь видит точное «Обновлений нет», а не неожиданный откат или скачок между ветками.
- **Dev требует одной ручной установки** — цена честного порядка semver. Автоматизация потребовала бы понятия канала, которого нет у старых клиентов.
