# Браузер встреч

Браузер встреч существует потому, что звонок проще записывать, когда страницу размещает сам Vibe: приложение управляет окном, знает, когда идёт запись, и может показать собственный интерфейс с единственным действием. Устройство продиктовано тем, что на самом деле позволяет операционная система.

## Почему схема URL, а не переходы по https

Браузер никогда не передаёт ссылку `https://` установленному приложению, если только это приложение не является браузером по умолчанию. Настольные приложения для встреч работают наоборот: они регистрируют собственную схему (`zoommtg://`, `msteams://`, `mattermost://`), и вызывают её их собственные страницы или установщики.

Vibe поступает так же честно:

- Включите **Открывать ссылки встреч в Vibe**, и Vibe зарегистрирует схемы встреч, которые уже используют Zoom, Teams и Webex (`zoommtg://`, `msteams://`, `webex://`), сопоставив каждую с веб-URL, который она несёт. Приложение проверяет URL в Rust и открывает его в окне браузера, если его хост может загружаться, а иначе — в системном браузере.
- URL `https`, переданный как аргумент запуска, проходит тем же путём.
- Внутри приложения источник **Браузер встреч** на главной странице и **Настройки → Запись → Открыть в Vibe** вставляют ссылку в тот же путь.

Vibe намеренно не поставляет собственную ссылку `vibe://open/`: ни одна страница встречи её не создаёт, поэтому эта первая точка входа была удалена. Щелчок по ссылке `https` в Chrome, Edge или Firefox по-прежнему открывает этот браузер. Сделать Vibe браузером по умолчанию намеренно не входит в задачу: это захватило бы все ссылки на машине ради одной функции и всё равно оставалось бы решением пользователя.

## Почему представление содержимого изолировано

Окно содержит два дочерних webview: интерфейс Vibe и удалённую страницу. Интерфейс принадлежит приложению и несёт его возможности; страница — обычное недоверенное веб-содержимое, у которого нет никаких возможностей, в неё не внедряются скрипты, а запросы доступа к камере и микрофону исходят от самой страницы, а не от Vibe, выдающего их от имени пользователя. Оба совместно используют среду WebView2 процесса, потому что WebView2 не поддерживает второй каталог данных в одном процессе.

Интерфейс предлагает адрес, назад, вперёд, обновить, закрыть и **Открыть в системном браузере**. Последнее действие — запасной выход для сервиса, который отказывается работать во встроенном webview. Встраивание нескольких webview — это возможность настольных Windows и Linux; на macOS браузер переключается на окно только со страницей, без интерфейса, а не отказывает.

## Почему браузер — это список разрешённых доменов

Встроенный браузер изначально загружал всё, что запрашивала страница; список хостов встреч лишь решал, какие ссылки получат панель записи. Теперь это настоящая граница: загружаться через https могут только разрешённые домены и их поддомены — как для страниц верхнего уровня, так и для каждого ресурса, который они запрашивают. Отклонённому ресурсу возвращается ответ с ошибкой, поэтому страница считает источник недоступным, а не повторяет попытки бесконечно.

У строгости есть цена: страница, тянущая шрифты или скрипты с CDN, ломается, пока этот CDN не разрешён. Список «Заблокированные» и есть решение — уникальные хосты, сначала новые, у каждого действие **Разрешить**, которое добавляет домен и перезагружает страницу. Список отрисовывается внутри интерфейса, и интерфейс растёт под него, потому что всплывающее окно внутри 104-пиксельного webview было бы обрезано страницей ниже. Интерфейс делает то же предложение, когда отклоняет переход. Windows реализует блокировку ресурсов с помощью `WebResourceRequested` из WebView2; Linux и macOS сейчас блокируют только навигацию верхнего уровня.

Режим кэшируется, а не читается для каждого окна, а фильтр ресурсов устанавливается в обоих режимах, поэтому переключение между `strict` и `trusted-site` доходит до уже открытой страницы при её следующем запросе, а не требует повторного открытия.

## Почему запись остаётся ручной

Каждая страница в браузере показывает **Записать встречу**, а пока открыто любое окно браузера, приглашение записать встречу во внешнем браузере подавляется. Запись по-прежнему ручная — нажмите кнопку до или во время звонка, остановите из интерфейса или из главного окна. Автоматический старт записывал бы звонки, которые пользователь не просил записывать, и заставлял бы индикатор микрофона приложения появляться без явного действия.

При закрытии окна во время записи приложение спрашивает, остановить или продолжить запись в фоне, поэтому уход из звонка не может молча отбросить запись или продолжить её.

## Ограничения

- Vibe передаётся только зарегистрированная схема встречи или аргумент запуска `https`. Для щелчка по `https` нужно решение о браузере по умолчанию, которое Vibe не принимает.
- Сайты с тяжёлым DRM или враждебные к WebRTC могут лучше работать в системном браузере; **Открыть в системном браузере** — поддерживаемый запасной вариант.
- Первой проверяется Windows. Остальные платформы используют собственные webview и переключаются на системный браузер, если окно не может разместить звонок.

Факты и правила списка разрешённых доменов — в [справочнике по браузеру встреч](../reference/meeting-browser.md); шаги — в [использовании браузера встреч](../how-to/use-the-meeting-browser.md).
