# Каналы обновлений

Приложение обновляется из одного из трёх файлов каналов на сайте, а не из последнего выпуска GitHub:

| Канал | Файл |
| --- | --- |
| Релиз | `https://kisev.github.io/vibe/updater/stable.json` |
| Beta | `https://kisev.github.io/vibe/updater/beta.json` |
| Dev | `https://kisev.github.io/vibe/updater/dev.json` |

Каждый файл — это `latest.json`, созданный релизной сборкой. Канал без файла — это ветка, на которой ничего нет: приложение сообщает «Обновлений нет», а не переключается на другой канал и не трактует отсутствующий файл как неудачную проверку.

## Ветки и версии

| Канал | Тег | Ветка | Версия | Что это |
| --- | --- | --- | --- | --- |
| Релиз | `vX.Y.Z` | `main` | `X.Y.Z` | Стабильная ветка |
| Beta | `vX.Y.Z-rc.<n>` | `main` | `X.Y.Z-rc.<n>` | Кандидат в следующую стабильную версию, публикуемый как предварительный выпуск GitHub |
| Dev | `dev.<n>` | `dev` | `<config>-dev.<n>.<sha>` | Подвижная сборка ветки `dev` |

`beta.json` отсутствует, пока не опубликован ни один кандидат. Обычный релиз отклоняется в канале beta; там принимается только `X.Y.Z-rc.<n>`.

## Откуда берутся манифесты

- **Релиз и beta**: средство обновления Tauri в релизной сборке создаёт `latest.json`. `scripts/channel.py <version> --channel <stable|beta>` скачивает его с `https://github.com/kisev/vibe/releases/download/v<version>/latest.json`, проверяет версию и записывает `website/public/updater/<channel>.json`. Закоммитьте файл в `main`; развёртывание сайта опубликует его.
- **Dev**: `.github/workflows/dev-build.yml` публикует предварительный выпуск с артефактами обновления и `latest.json`. `scripts/dev_manifest.py` читает новейший полный dev-выпуск и записывает `website/public/updater/dev.json`; свежая dev-сборка запускает развёртывание сайта. Если новейший выпуск неполон или вызов API завершается ошибкой, предыдущий `dev.json` остаётся.

`channel.py` отказывается перемещать канал назад и понимает порядок `-rc.<n>`.

## В приложении

- **Настройки → Общие → Обновления** содержит выбор канала, текущую версию, **Проверить обновления**, время последней проверки и результат.
- Выбор во время выполнения находится в `desktop/src-tauri/src/updater.rs`; сторона webview — `desktop/src/providers/updater.tsx`.
- `desktop/src-tauri/src/updater.rs` запрашивает `updater/<channel>.json` напрямую. `404` или `410` означают, что канал никогда не публиковался; любая другая ошибка — настоящая.
- Статический адрес плагина Tauri в `tauri.conf.json` — запасной вариант, о котором знает сам плагин; выбор канала происходит в коде приложения.

## Границы

- Обновление идёт только вперёд. Плохая сборка исправляется выпуском более новой.
- Установка релиза или beta, выбравшая Dev, видит «Обновлений нет»: каждая dev-сборка ниже уже установленной версии. Переход на ветку dev требует одной ручной установки dev-сборки; после этого канал Dev обновляет её дальше.
- Установка Beta переходит на финальный релиз переключением на Релиз, где `X.Y.Z` выше своих кандидатов.
- Приложения, собранные до появления файлов каналов (линейка 3.x от upstream), по-прежнему читают тот выпуск GitHub, который помечен как «latest». Именно `gh release edit --latest` доставляется им, и запускается он последним.

См. [Публикация релиза](../how-to/publish-a-release.md) и [Создание dev-сборки](../how-to/cut-a-dev-build.md) для процедур, а [объяснение](../explanation/update-channels.md) — о том, почему ветки и суффиксы устроены именно так.
