# 회의 브라우저가 이렇게 동작하는 이유

Vibe가 페이지를 직접 호스팅하면 통화를 더 쉽게 녹음할 수 있습니다. 앱이 창을 제어하고, 녹음이 진행 중인지 알고, 동작 하나만 있는 표시줄을 보여 줄 수 있습니다. 설계는 운영 체제가 실제로 허용하는 것에 맞춰져 있습니다.

## https 클릭 대신 URL 스킴을 쓰는 이유

브라우저는 설치된 앱이 기본 브라우저가 아니면 `https://` 링크를 그 앱에 넘기지 않습니다. 회의 앱은 반대로 동작합니다: 자체 스킴을 등록하고 그 페이지나 설치 프로그램이 이를 호출합니다.

Vibe도 같은 방식을 씁니다:

- `vibe://open/?url=https://…`는 Vibe의 브라우저 창에서 대상을 엽니다. 어떤 앱, 스크립트, 단축키든 호출할 수 있습니다. Vibe는 Rust에서 URL을 검증하고 https이며 올바른 형식이 아닌 것은 거부합니다.
- **설정 → 녹음 → Vibe에서 열기**는 링크를 같은 경로에 붙여넣습니다.

Chrome, Edge, Firefox에서 `https` 링크를 클릭하면 여전히 그 브라우저가 열립니다. Vibe를 기본 브라우저로 만드는 것은 의도적으로 범위 밖입니다. 기능 하나를 위해 기기의 모든 링크를 가져오게 되기 때문입니다.

## 콘텐츠 보기가 격리된 이유

콘텐츠 창은 자체 데이터 디렉터리를 가진 평범한 웹뷰입니다. 서비스 쿠키는 앱 저장소와 섞이지 않고, 페이지에 스크립트가 주입되지 않으며, 카메라와 마이크 프롬프트는 Vibe가 사용자 대신 허용하는 것이 아니라 페이지 자체에서 나옵니다. 삽입된 페이지는 앱의 일부가 아니라 신뢰할 수 없는 웹 콘텐츠로 취급됩니다.

표시줄은 주소, 뒤로, 앞으로, 새로고침, 닫기, **시스템 브라우저에서 열기**를 제공합니다. 마지막 동작은 삽입된 웹뷰에서 실행되기를 거부하는 서비스를 위한 탈출구입니다.

## 녹음이 수동으로 유지되는 이유

회의 목록의 호스트는 창을 회의 세션으로 바꿉니다. 표시줄에 **이 회의 녹음**이 표시됩니다. 녹음은 여전히 수동입니다. 통화 전이나 도중에 버튼을 누르고, 표시줄이나 메인 창에서 중지합니다. 자동 시작은 사용자가 요청하지 않은 통화를 녹음하고, 명시적 동작 없이 마이크 표시기가 나타나게 합니다.

녹음 중에 창을 닫으면 중지할지 백그라운드에서 계속 녹음할지 묻습니다. 따라서 통화를 떠난다고 해서 녹음이 조용히 폐기되거나 계속되지 않습니다.

## 제한

- 자동으로 열리는 것은 `vibe://open/` 링크뿐입니다. `https` 클릭에는 Vibe가 하지 않는 기본 브라우저 결정이 필요합니다.
- DRM이 많거나 WebRTC를 싫어하는 사이트는 시스템 브라우저에서 더 잘 작동할 수 있습니다. **시스템 브라우저에서 열기**가 지원되는 대체 경로입니다.
- Windows가 먼저 검증됩니다. 다른 플랫폼은 자체 웹뷰를 사용하며, 창이 통화를 호스팅할 수 없으면 시스템 브라우저로 대체합니다.
- Zoom, Teams, Webex 스킴 등록은 선택 사항이며 macOS가 아니라 Windows와 Linux에서 사용할 수 있습니다.
