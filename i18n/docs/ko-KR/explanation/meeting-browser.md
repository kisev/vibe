# 회의 브라우저

회의 브라우저가 있는 이유는 Vibe가 페이지를 직접 호스팅할 때 통화를 더 쉽게 녹음할 수 있기 때문입니다: 앱이 창을 제어하고, 녹음이 진행 중인지 알고, 동작 하나로 자체 표시줄을 보여 줄 수 있습니다. 설계는 운영 체제가 실제로 허용하는 것에 맞춰져 있습니다.

## https 클릭 대신 URL 스킴을 쓰는 이유

브라우저는 설치된 앱이 기본 브라우저가 아니면 `https://` 링크를 그 앱에 넘기지 않습니다. 데스크톱 회의 앱은 반대로 동작합니다: 자체 스킴(`zoommtg://`, `msteams://`, `mattermost://`)을 등록하고, 자체 페이지나 설치 프로그램이 이를 호출합니다.

Vibe도 같은 방식을 씁니다:

- **Vibe에서 회의 링크 열기**를 켜면 Vibe가 Zoom, Teams, Webex가 이미 사용하는 회의 스킴(`zoommtg://`, `msteams://`, `webex://`)을 등록하고, 각 스킴을 그것이 전달하는 웹 URL에 매핑합니다. 앱은 Rust에서 URL을 검증하고, 호스트를 로드할 수 있으면 브라우저 창에서, 아니면 시스템 브라우저에서 엽니다.
- 실행 인수로 전달된 `https` URL도 같은 경로를 거칩니다.
- 앱 안에서는 홈 페이지의 **회의 브라우저** 소스와 **설정 → 녹음 → Vibe에서 열기**가 링크를 같은 경로에 붙여넣습니다.

Vibe는 의도적으로 자체 `vibe://open/` 링크를 제공하지 않습니다: 어떤 회의 페이지도 이러한 링크를 내보내지 않기 때문에 첫 번째 진입점이 제거되었습니다. Chrome, Edge, Firefox에서 `https` 링크를 클릭하면 여전히 그 브라우저가 열립니다. Vibe를 기본 브라우저로 만드는 것은 의도적으로 범위 밖입니다: 기능 하나를 위해 기기의 모든 링크를 가져오게 되고, 결국 사용자가 결정할 일이기 때문입니다.

## 콘텐츠 보기가 격리된 이유

창에는 두 개의 자식 웹뷰가 있습니다: Vibe의 표시줄과 원격 페이지입니다. 표시줄은 앱 UI이며 앱의 기능을 갖습니다. 페이지는 아무런 기능도 없는 평범한 신뢰할 수 없는 웹 콘텐츠로, 스크립트가 주입되지 않고, 카메라와 마이크 프롬프트는 Vibe가 사용자 대신 허용하는 것이 아니라 페이지 자체에서 나옵니다. 둘은 프로세스의 WebView2 환경을 공유하는데, WebView2가 한 프로세스에서 두 번째 데이터 디렉터리를 지원하지 않기 때문입니다.

표시줄은 주소, 뒤로, 앞으로, 새로고침, 닫기, **시스템 브라우저에서 열기**를 제공합니다. 마지막 동작은 삽입된 웹뷰에서 실행되기를 거부하는 서비스를 위한 탈출구입니다. 다중 웹뷰 삽입은 여기서 데스크톱 Windows/Linux 기능입니다. macOS에서는 실패하는 대신 표시줄이 없는 페이지 전용 창으로 대체됩니다.

## 브라우저가 허용 목록인 이유

삽입된 브라우저는 원래 페이지가 요청하는 것은 무엇이든 로드했습니다. 회의 호스트 목록은 어떤 링크에 녹음 표시줄을 붙일지만 결정했습니다. 이제는 실제 경계입니다: 허용된 도메인과 그 하위 도메인만 https를 통해 로드될 수 있으며, 최상위 페이지와 페이지가 요청하는 모든 리소스 모두 마찬가지입니다. 거부된 리소스에는 오류 응답이 반환되어 페이지가 해당 오리진을 사용할 수 없는 것으로 처리하고 무한히 재시도하지 않습니다.

엄격함에는 비용이 따릅니다: CDN에서 글꼴이나 스크립트를 가져오는 페이지는 해당 CDN이 허용될 때까지 깨집니다. 차단됨 목록이 그 해결책입니다. 고유한 호스트가 최신 순으로 표시되며, 각각 도메인을 추가하고 페이지를 다시 로드하는 **허용** 동작이 있습니다. 목록은 표시줄 안에 그려지고 표시줄이 목록에 맞게 커지는데, 104-pixel 웹뷰 안의 팝업은 아래 페이지에 의해 잘리기 때문입니다. 표시줄은 탐색을 거부할 때도 같은 제안을 합니다. Windows는 WebView2의 `WebResourceRequested`로 리소스 차단을 적용합니다. Linux와 macOS는 현재 최상위 탐색만 차단합니다.

모드는 창마다 읽지 않고 캐시되며, 리소스 필터는 두 모드 모두에서 설치되므로 `strict`와 `trusted-site` 사이를 전환하면 이미 열려 있는 페이지가 다시 열 필요 없이 다음 요청에서 새 모드에 도달합니다.

## 녹음이 수동으로 유지되는 이유

브라우저의 모든 페이지에는 **이 회의 녹음**이 표시되며, 브라우저 창이 하나라도 열려 있는 동안 외부 브라우저 회의 프롬프트는 표시되지 않습니다. 녹음은 여전히 수동입니다. 통화 전이나 도중에 버튼을 누르고, 표시줄이나 메인 창에서 중지합니다. 자동 시작은 사용자가 요청하지 않은 통화를 녹음하고, 명시적 동작 없이 앱의 마이크 표시기가 나타나게 합니다.

녹음 중에 창을 닫으면 중지할지 백그라운드에서 계속 녹음할지 묻습니다. 따라서 통화를 떠난다고 해서 녹음이 조용히 폐기되거나 계속되지 않습니다.

## 제한

- 등록된 회의 스킴이나 `https` 실행 인수만 Vibe로 전달됩니다. `https` 클릭에는 Vibe가 하지 않는 기본 브라우저 결정이 필요합니다.
- DRM이 많거나 WebRTC를 싫어하는 사이트는 시스템 브라우저에서 더 잘 작동할 수 있습니다. **시스템 브라우저에서 열기**가 지원되는 대체 경로입니다.
- Windows가 먼저 검증됩니다. 다른 플랫폼은 자체 웹뷰를 사용하며, 창이 통화를 호스팅할 수 없으면 시스템 브라우저로 대체합니다.

세부 사실과 허용 목록 규칙은 [회의 브라우저 참조](../reference/meeting-browser.md)에, 단계는 [회의 브라우저 사용](../how-to/use-the-meeting-browser.md)에 있습니다.
