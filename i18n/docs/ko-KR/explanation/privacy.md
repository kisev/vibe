# 프라이버시와 오프라인 설계

Vibe는 일반적인 트랜스크립션 경로에 계정도 클라우드 서비스도 필요 없도록 만들어졌습니다. 앱이 로컬 서버를 시작하고, 서버가 디스크에서 모델을 불러오며, 오디오는 같은 기기에서 디코딩되고 받아쓰입니다.

## 로컬에 남는 것

- 오디오 파일, 녹음, 내보내기, 전사.
- 모델과 ffmpeg 바이너리.
- 프로젝트 폴더의 프로젝트 기록.
- 데스크톱 앱과 `vibe-server` 사이의 로컬 HTTP API로, 루프백에 바인딩됩니다.

앱은 텔레메트리를 보내지 않습니다. **문제 보고하기**는 로컬 진단으로 미리 채워진 이슈를 만들어 GitHub를 열며, 검토하고 보내기 전까지는 아무것도 제출되지 않습니다.

## 네트워크가 사용되는 곳

| 기능 | 네트워크 접촉 |
| --- | --- |
| 모델 다운로드 | 모델 파일을 제공하는 호스트 |
| 링크에서 받아쓰기 | 미디어 호스트, yt-dlp 바이너리용 GitHub |
| 업데이트 확인 | 웹사이트 채널 파일 |
| Claude 또는 OpenAI를 사용한 AI 요약 | 구성한 공급자 |
| Ollama를 사용한 AI 요약 | Ollama URL, 기본값은 로컬 |
| 휴대폰 연동 | 휴대폰과 이 컴퓨터 사이의 종단 간 암호화 중계 |

받아쓰기 엔진 자체에는 네트워크 경로가 없습니다.

## 휴대폰 연동

휴대폰과 데스크톱은 iroh를 통해 연결됩니다. 중계 서버는 종단 간 암호화된 트래픽을 전달하므로 읽을 수 없는 바이트를 전달합니다. 받아쓰기는 여전히 이 컴퓨터에서 일어나며, 연동이 작동하려면 Vibe가 열려 있어야 합니다.

## 트레이드오프

- 로컬 모델은 디스크 공간을 차지하고 컴퓨터의 CPU 또는 GPU를 사용합니다. [엔진과 GPU 선택](/vibe/docs#engine)이 그 분담을 설명합니다.
- 클라우드 요약은 전사 텍스트를 선택한 공급자에게 보냅니다. 로컬에 두려면 플랫폼을 Ollama로 두세요.
- 업데이트는 웹사이트의 정적 파일에서 확인하므로, 앱이 채널을 확인했다는 것만 드러나고 무엇을 받아썼는지는 드러나지 않습니다.

## 관련 페이지

- 로컬 설정 파일은 [설정 및 구성](/vibe/docs#settings).
- 연동 단계는 [휴대폰에서 받아쓰기](/vibe/docs#transcribe-from-a-phone).
- AI 플랫폼은 [전사 요약](/vibe/docs#summarize-transcripts).
