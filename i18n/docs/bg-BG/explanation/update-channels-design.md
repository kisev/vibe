# Защо каналите за актуализации работят така

GitHub има едно „latest release“. Vibe се нуждае от три линии — Release, Beta и Dev — между които потребителят може да превключва, включително от по-стара инсталация. Това несъответствие определя дизайна на каналите.

## Защо уебсайтът, а не GitHub

Приложението чете `updater/<channel>.json` от уебсайта. Всеки файл е `latest.json`, който е произвела компилация за издание, копиран до останалите:

- Release → `stable.json`
- Beta → `beta.json`
- Dev → `dev.json`

Файлът на канал е статичен ресурс, публикуван със сайта, така че насочването на линия към компилация е комит, а не редакция на издание. Това също позволява липсващият канал да значи нещо точно: `404` или `410` е „нищо на тази линия“, което приложението показва като най-нова версия. Ако приложението преминаваше към друг канал при липсващ файл, потребител на Beta без кандидат тихо би се преместил в Release.

## Защо наставката на бета е `-rc.<n>`

Semver подрежда:

```text
X.Y.Z-dev.N < X.Y.Z-rc.N < X.Y.Z
```

Тази подредба е цялата причина за изписването. При строгото сравнение на програмата за актуализация Dev → Beta → Release винаги се движи напред; не е нужно специално изключение.

По-ранна линия използваше `-beta.N`, но тя нямаше dev канал. `X.Y.Z-beta.N` се подрежда над `X.Y.Z-dev.N`, така че бета компилация би изглеждала по-нова от всяка dev компилация и би счупила превключването. Бета каналът запазва името си; само наставката на версията е `-rc.<n>`.

## Защо бета носи само кандидати

Само версия `X.Y.Z-rc.<n>` се записва в `beta.json`; обикновено издание се отхвърля. Това запазва смисъла на бета линията: тя е линията на кандидатите, а не втора стабилна линия. След стабилно издание инсталация Beta преминава към финалното чрез превключване на канала си към Release, където `X.Y.Z` се подрежда над кандидатите си.

## Актуализации само напред

Програмата за актуализация се движи само напред. Лошо издание се поправя, като се публикува по-ново, за което служи бета линията: да го хване, преди Release да го получи. Затова и инсталация Release или Beta, която избере Dev, вижда „Най-нова версия“: всяка dev компилация се подрежда под версията, която вече работи. Преминаването към dev линията изисква едно ръчно инсталиране на dev компилация; след това каналът Dev я актуализира напред.

## Компромиси

- **Копираните манифести** означават, че смяната на канал е комит към `main` плюс публикуване на сайта, а не API заявка. Закъснението е минути, а историята е прегледима.
- **Без резервен вариант между каналите** означава, че потребителят вижда точно „Най-нова версия“, вместо изненадващо понижение или скок между линии.
- **Dev изисква едно ръчно инсталиране** е цената за честна подредба по semver. Автоматизирането му би изисквало концепция за канал, която старите клиенти нямат.
