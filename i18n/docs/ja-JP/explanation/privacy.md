# プライバシーとオフライン設計

Vibe は、通常の文字起こしの流れがアカウントもクラウドサービスも必要としないように作られています。アプリはローカルサーバーを起動し、サーバーはディスクからモデルを読み込み、音声は同じマシン上でデコードされ、文字起こしされます。

## ローカルに留まるもの

- 音声ファイル、録音、エクスポート、文字起こし。
- モデルと ffmpeg バイナリ。
- プロジェクトフォルダー内のプロジェクト履歴。
- デスクトップアプリと `vibe-server` の間のローカル HTTP API。ループバックにバインドされます。

アプリはテレメトリを送信しません。**問題を報告** はローカルの診断情報から記入済みの課題を作成して GitHub を開きます。内容を確認して送信するまで、何も送信されません。

## ネットワークが使われる場所

| 機能 | ネットワーク接続 |
| --- | --- |
| モデルのダウンロード | モデルファイルを提供するホスト |
| リンクからの文字起こし | メディアのホスト、および yt-dlp バイナリのための GitHub |
| アップデートの確認 | ウェブサイトのチャンネルファイル |
| Claude または OpenAI による AI 要約 | 設定したプロバイダー |
| Ollama による AI 要約 | Ollama の URL。デフォルトではローカル |
| スマートフォン連携 | スマートフォンとこのコンピューターの間のエンドツーエンド暗号化中継 |

文字起こしエンジン自体にはネットワーク経路がありません。

## スマートフォン連携

スマートフォンとデスクトップは iroh 経由で接続します。中継はエンドツーエンドで暗号化されたトラフィックを運ぶため、中継は読めないバイトを転送するだけです。文字起こしは引き続きこのコンピューターで行われ、連携が機能するには Vibe を開いたままにする必要があります。

## トレードオフ

- ローカルモデルはディスク容量を使い、マシンの CPU または GPU を使用します。[エンジンと GPU の選択](/vibe/docs#engine)で分担を説明しています。
- クラウドの要約は、文字起こしのテキストを選択したプロバイダーに送ります。ローカルに保つには、プラットフォームを Ollama のままにしてください。
- アップデートはウェブサイト上の静的ファイルから確認されるため、アプリがチャンネルを確認したことは分かりますが、何を文字起こししたかは分かりません。
