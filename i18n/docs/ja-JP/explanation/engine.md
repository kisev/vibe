# エンジンと GPU の選択

Vibe はデスクトップシェルと文字起こしエンジンを分離しています。シェルは Rust と React の Tauri アプリで、エンジンは `vibe-server` です。これは ggml 上の transcribe.cpp C++ ライブラリを呼び出す Rust プロセスです。

## エンジンが別プロセスである理由

サーバーはモデルの読み込みと重い計算を担います。デスクトッププロセスから切り離しておくと、次の利点があります:

- マルチギガバイトのモデルを再読み込みせずにウィンドウを再起動できる。
- 同じバイナリがアプリ、CLI、ローカル HTTP API に使える。
- エンジンでのクラッシュがウィンドウを巻き込まない。
- エンジンを独自のスケジュールで更新でき、アプリのビルドで固定される。

デスクトップアプリはローカル HTTP 経由でサーバーと通信します。この経路のどこもマシンの外に出ません。ネットワークの範囲については[プライバシーとオフライン設計](/vibe/docs#privacy)で説明しています。

## 1 つのエンジン、多くのモデルファミリー

対応するすべてのファミリーは同じ ggml ビルドを通じて動作します: Whisper、Parakeet、Nemotron、Canary、Qwen3-ASR、Voxtral、GigaAM です。Silero VAD と Nemotron-3 の話者分離も同じスタックで動作します。エンジンが 1 つであることで、メモリ処理、量子化、GPU ディスパッチがすべてのモデルで同じになります。

トレードオフはバージョンの結合です。GGUF が同梱ビルドより新しい transcribe.cpp を必要とするモデルは、[モデル](/vibe/docs#models)に一覧されていますが、エンジンが更新されるまで読み込めません。この固定は意図的なものです。エンジンのアップグレードはバックグラウンドの依存関係更新ではなく、パリティのイベントだからです。

## GPU バックエンド

ggml は実行するマシンに合わせてバックエンドを選びます:

| プラットフォーム | バックエンド |
| --- | --- |
| macOS | Metal |
| Windows | Vulkan |
| Linux | Vulkan |

使用可能な GPU がないマシンは CPU で動作します。**設定 → モデル** には **CPUで文字起こしする** と、Windows と Linux では GPU デバイスピッカーがあります。GPU の読み込みに失敗すると、アプリは CPU で再試行し、その旨を報告します。

GPU は大きなモデルと長いファイルで最も重要です。最新の CPU では小さなモデルでも十分に高速なことがあり、ドライバーや Vulkan ローダーがない場合のフォールバックが CPU 経路です。
