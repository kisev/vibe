# 会議ブラウザ

会議ブラウザがあるのは、Vibe がページ自体をホストすると通話の録音が簡単になるからです。アプリがウィンドウを制御し、録音中かどうかを把握し、1 つの操作で独自の UI を表示できるようになります。設計は、オペレーティングシステムが実際に許可する内容に形作られています。

## https のクリックではなく URL スキームを使う理由

ブラウザは、そのアプリがデフォルトブラウザでない限り、`https://` リンクをインストール済みアプリに渡すことはありません。デスクトップの会議アプリは逆の方法で動作します。独自のスキーム（`zoommtg://`、`msteams://`、`mattermost://`）を登録し、自身のページやインストーラーがそれを呼び出します。

Vibe も同じ率直な方法を取ります:

- **Vibe で会議リンクを開く** をオンにすると、Vibe は Zoom、Teams、Webex がすでに使っている会議スキーム（`zoommtg://`、`msteams://`、`webex://`）を登録し、それぞれが運ぶウェブ URL にマッピングします。アプリは Rust で URL を検証し、ホストの読み込みが許可されている場合はブラウザウィンドウで、そうでない場合はシステムのブラウザで開きます。
- 起動引数として渡された `https` URL も同じ経路を通ります。
- アプリ内では、ホームページの **会議ブラウザ** ソースと **設定 → 録音 → Vibe で開く** にリンクを貼り付けると、同じ経路に入ります。

Vibe は意図的に独自の `vibe://open/` リンクを提供していません。会議ページがそれを出力することはなく、最初のエントリポイントが削除されたのはそのためです。Chrome、Edge、Firefox で `https` リンクをクリックしても、そのブラウザが開きます。Vibe をデフォルトブラウザにすることは意図的に対象外です。1 つの機能のためにマシン上のすべてのリンクを引き受けることになり、しかもそれはユーザーの判断であるべきだからです。

## コンテンツビューが分離されている理由

ウィンドウには 2 つの子 webview が入っています。Vibe のバーとリモートページです。バーはアプリの UI であり、アプリのケイパビリティを持ちます。ページはまったくケイパビリティを持たない通常の信頼されないウェブコンテンツで、スクリプトは注入されず、カメラとマイクのプロンプトは Vibe がユーザーに代わって許可するのではなく、ページ自体から出ます。両方はプロセスの WebView2 環境を共有します。WebView2 は 1 つのプロセスで 2 つ目のデータディレクトリをサポートしていないためです。

バーにはアドレス、戻る、進む、再読み込み、閉じる、**システムのブラウザで開く** があります。最後の操作は、埋め込み webview での動作を拒否するサービスのための逃げ道です。複数の webview の埋め込みは、ここではデスクトップの Windows/Linux の機能です。macOS では、ブラウザは失敗するのではなく、バーのないページのみのウィンドウにフォールバックします。

## ブラウザが許可リストである理由

埋め込みブラウザはもともと、ページが要求するものをすべて読み込んでいました。会議ホストの一覧は、どのリンクに録音バーを付けるかだけを決めていました。現在は実際の境界です。許可されたドメインとそのサブドメインのみが https 経由で読み込まれ、トップレベルのページにも、ページが要求するすべてのリソースにも適用されます。拒否されたリソースにはエラー応答が返されるため、ページはそのオリジンを利用不可として扱い、無限に再試行しません。

厳格さにはコストが伴います。フォントやスクリプトを CDN から取得するページは、その CDN が許可されるまで壊れます。ブロック中の一覧がその対処法です。一意のホストが新しい順に並び、それぞれにドメインを追加してページを再読み込みする **許可** 操作があります。一覧はバーの中に描画され、バーはそれに合わせて大きくなります。104-pixel の webview 内のポップアップは下のページで切り取られてしまうからです。バーは、ナビゲーションを拒否するときにも同じ提案をします。Windows は WebView2 の `WebResourceRequested` でリソースのブロックを実施します。Linux と macOS は現在、トップレベルのナビゲーションのみをブロックします。

モードはウィンドウごとに読み取るのではなくキャッシュされ、リソースフィルターは両方のモードでインストールされます。そのため、`strict` と `trusted-site` を切り替えると、開き直すことなく、すでに開いているページに次のリクエストから反映されます。

## 録音が手動のままである理由

ブラウザのすべてのページに **この通話を録音** が表示され、ブラウザウィンドウが開いている間は外部ブラウザ向けの会議プロンプトが抑制されます。録音は依然として手動です。通話の前または通話中にボタンを押し、バーまたはメインウィンドウから停止します。自動開始は、ユーザーが録音を求めていない通話を録音してしまい、明示的な操作なしにアプリのマイクインジケーターを表示させることになります。

録音中にウィンドウを閉じると、停止するかバックグラウンドで録音を続けるかを確認されるため、通話から離れても録音が黙って破棄されたり継続されたりすることはありません。

## 制限

- Vibe に渡されるのは、登録された会議スキームまたは `https` の起動引数のみです。`https` のクリックには、Vibe が取らないデフォルトブラウザの判断が必要です。
- DRM の多いサイトや WebRTC に厳しいサイトは、システムのブラウザのほうがうまく動作することがあります。**システムのブラウザで開く** がサポートされるフォールバックです。
- Windows が最初に検証されています。他のプラットフォームは独自の webview を使い、ウィンドウで通話をホストできない場合はシステムのブラウザにフォールバックします。

事実と許可リストのルールは[会議ブラウザのリファレンス](../reference/meeting-browser.md)に、手順は[会議ブラウザを使う](../how-to/use-the-meeting-browser.md)にあります。
