# 会議ブラウザがこの仕組みである理由

Vibe がページ自体をホストすると、通話の録音が簡単になります。アプリがウィンドウを制御し、録音中かどうかを把握し、1 つの操作を持つバーを表示できるからです。設計はオペレーティングシステムが実際に許可する内容に形作られています。

## https のクリックではなく URL スキームを使う理由

ブラウザは、そのアプリがデフォルトブラウザでない限り、`https://` リンクをインストール済みアプリに渡すことはありません。会議アプリは逆の方法で動作します。独自のスキームを登録し、ページやインストーラーがそれを呼び出します。

Vibe も同じことをします:

- `vibe://open/?url=https://…` は対象を Vibe のブラウザウィンドウで開きます。任意のアプリ、スクリプト、ショートカットから呼び出せます。Vibe は Rust で URL を検証し、https でないものや整形式でないものを拒否します。
- **設定 → 録音 → Vibe で開く** はリンクを同じ経路に貼り付けます。

Chrome、Edge、Firefox で `https` リンクをクリックしても、そのブラウザが開きます。Vibe をデフォルトブラウザにすることは意図的に対象外です。1 つの機能のためにマシン上のすべてのリンクを引き受けることになるからです。

## コンテンツビューが分離されている理由

コンテンツウィンドウは独自のデータディレクトリを持つ通常の webview です。サービスの Cookie がアプリのストレージと混ざることはなく、ページにスクリプトが注入されることもなく、カメラとマイクのプロンプトは Vibe がユーザーに代わって許可するのではなく、ページ自体から出ます。埋め込まれたページはアプリの一部ではなく、信頼されないウェブコンテンツとして扱われます。

バーにはアドレス、戻る、進む、再読み込み、閉じる、**システムのブラウザで開く** があります。最後の操作は、埋め込み webview での動作を拒否するサービスのための逃げ道です。

## 録音が手動のままである理由

会議一覧のホストはウィンドウを会議セッションに変えます。バーに **この通話を録音** が表示されます。録音は依然として手動です。通話の前または通話中にボタンを押し、バーまたはメインウィンドウから停止します。自動開始は、ユーザーが録音を求めていない通話を録音してしまい、明示的な操作なしにマイクインジケーターを表示させることになります。

録音中にウィンドウを閉じると、停止するかバックグラウンドで録音を続けるかを確認されるため、通話から離れても録音が黙って破棄されたり継続されたりすることはありません。

## 制限

- 自動的に開くのは `vibe://open/` リンクのみです。`https` のクリックには、Vibe が取らないデフォルトブラウザの判断が必要です。
- DRM の多いサイトや WebRTC に厳しいサイトは、システムのブラウザのほうがうまく動作することがあります。**システムのブラウザで開く** がサポートされるフォールバックです。
- Windows が最初に検証されています。他のプラットフォームは独自の webview を使用し、ウィンドウで通話をホストできない場合はシステムのブラウザにフォールバックします。
- Zoom、Teams、Webex のスキームの登録はオプトインで、Windows と Linux で利用でき、macOS では利用できません。
