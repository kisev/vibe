# המנוע ובחירות GPU

Vibe מפריד את מעטפת השולחן ממנוע התמלול. המעטפת היא אפליקציית Tauri ב-Rust ו-React; המנוע הוא `vibe-server`, תהליך Rust שקורא לספריית ה-C++ transcribe.cpp על ggml.

## למה המנוע הוא תהליך נפרד

השרת אחראי על טעינת המודלים ועל החישוב הכבד. הרחקתו מתהליך השולחן פירושה:

- החלון יכול לעלות מחדש בלי לטעון מחדש מודל של כמה גיגה-בייט;
- אותו בינארי משרת את האפליקציה, את ה-CLI ואת ה-API המקומי ב-HTTP;
- קריסה במנוע לא לוקחת איתה את החלון;
- ניתן לעדכן את המנוע בלוח הזמנים שלו, כשהוא מוצמד לבילד האפליקציה.

אפליקציית השולחן מדברת עם השרת דרך HTTP מקומי. שום דבר בנתיב הזה לא יוצא מהמחשב; [פרטיות ועיצוב לא מקוון](/vibe/docs#privacy) מכסה את משטח הרשת.

## מנוע אחד, משפחות מודלים רבות

כל משפחה נתמכת רצה דרך אותו בילד ggml: Whisper, Parakeet, Nemotron, Canary, Qwen3-ASR, Voxtral ו-GigaAM. Silero VAD וזיהוי הדוברים של Nemotron-3 גם רצים על אותו סטאק. מנוע אחד שומר על טיפול בזיכרון, קוונטיזציה ושיגור GPU זהים לכל מודל.

הפשרה היא צימוד גרסאות: מודל שה-GGUF שלו דורש transcribe.cpp חדש יותר מהבילד המצורף מופיע ב[מודלים](/vibe/docs#models) אבל לא יכול להיטען עד שהמנוע מתקדם. ההצמדה הזו מכוונת, כי שדרוגי מנוע הם אירועי יישור קו, לא עדכוני תלות ברקע.

## Backends של GPU

ggml בוחר backend למכונה שעליה הוא רץ:

| פלטפורמה | Backend |
| --- | --- |
| macOS | Metal |
| Windows | Vulkan |
| Linux | Vulkan |

מכונה בלי GPU שמיש רצה על ה-CPU. **הגדרות → מודלים** נושא את **תמלול על ה-CPU** וב-Windows וב-Linux גם בורר התקן GPU. אם טעינת GPU נכשלת, האפליקציה מנסה שוב על ה-CPU ומדווחת שעשתה זאת.

ה-GPU חשוב ביותר למודלים גדולים ולקבצים ארוכים. מודלים קטנים על CPU מודרני יכולים להיות מהירים מספיק, ונתיב ה-CPU הוא הנפילה החזרה כשאין דרייבר או מטען Vulkan.
