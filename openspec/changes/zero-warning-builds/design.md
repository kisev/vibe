# Design

## Context

See `proposal.md` — Why. The warnings split into four kinds: mechanical lint findings (the bulk), two API-shape findings, generated FFI code, and one stale sentence in a change artifact. Nothing here changes behavior, so the design is mostly about which fixes are safe and where suppression is the honest answer.

## Goals / Non-Goals

**Goals:**

- `cargo clippy --workspace --tests` in `server/` and `cargo check --tests` for the desktop crate report zero warnings.
- Fixes that a reader can review without knowing the lints; no blanket `#![allow(clippy::all)]` in first-party code.
- The design record of `close-longform-verification-gaps` matches the shipped error wrapping.

**Non-Goals:**

- No behavior change of any kind; no new clippy lint levels or CI gates.
- No cleanup of `ggml-rs-sys` beyond silencing its generated output.

## Decisions

### Mechanical fixes go through `cargo clippy --fix` first

The excessive-precision floats in `gigaam-rs` tests (73 sites), `chunks_exact` in `whisper-rs`, `div_ceil` in the encoder, and the loop-variable indexing in the decoder all have exact clippy suggestions. Applying them mechanically keeps the diff boring; float literals round to the nearest `f32`, which is bit-identical to the current value. Anything the fixer cannot express — `push_str(" ")` to `push(' ')`, removing the dead `MINUTE` constant, moving `TranscribeArgs` above the test module, `unwrap_or_else` to `unwrap_or`, `match` to `?` — is edited by hand with the same shape.

### The two API-shape findings get real refactors, not allows

- `stream_transcription` takes eight parameters because the caller pulled apart the request; the pieces become a `StreamRequest`-style struct built at the call site, so the signature reads as one thing.
- `transcribe` and the transcriptions handler return `Result<Response, Response>`, which clippy flags as a large `Err`. `stream.rs` already returns `Result<Response, Box<Response>>` for exactly this reason; the two stragglers switch to the same boxed shape, and `format_response`'s error path boxes on construction.

### Generated FFI code is suppressed at the crate, not edited

`ggml-rs-sys`'s warnings all point into `target/…/bindings.rs`, regenerated by bindgen on every build; hand edits vanish and per-line allows cannot be placed. The crate's `lib.rs` gains targeted `#![allow(...)]` attributes naming the three lint families the generator trips (transmutes, offset casts, missing `# Safety` docs), with a comment saying why. First-party code in the crate keeps full linting.

### The desktop `bail!` warnings are fixed at the sites

Eight occurrences end `bail!("…");` where the macro is the arm's value expression; dropping the semicolon restores expression position. This is the warning the user hit by hand earlier, so the fix lands in the code rather than an allow.

## Risks / Trade-offs

- **A large mechanical diff hides a real change** → apply clippy's fixer per crate and review the residual diff by hand; the float literals and `chunks_exact` rewrites are the only bulk edits and are semantically identity.
- **Signature changes ripple to callers** → both refactors touch one call site each; the full suites gate them.
- **Allows could mask future real warnings in `ggml-rs-sys`** → the allows name the three generated lint families only, and hand-written code in that crate stays fully linted.

## Migration Plan

Single commit-sized sweep, no data or API contract changes. Rollback is a revert.
